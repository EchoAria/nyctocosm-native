## 3. 先补齐每项的可执行规格，再动实现

逐项方案是设计，不是已经完整导出的数值表。实施者必须继续读取该 D 项引用的生成分支/动画命令，不得凭技能名、粒子图案或旧测试断言猜参数。在 `nyctocosm-native/docs/validation/` 为该项新建有 D 编号的规格/验收记录（不覆盖旧日志），至少包含：

1. **可达链：** 运行入口→选择条件→动画 leaf/生成分支→独立 tick→命中→终止，记录具体路径、命令/方法及必要的源文件哈希。
2. **时间：** 世界 tick、动画帧、独立计分器、每 tick 子步各自起点；同 tick 的调用顺序、先加/后判、即时执行、跳帧/重入。缺失的 scoreboard 值不能一律等同数值 0。
3. **空间：** 维度与缩放、世界/局部偏移、yaw/pitch、手/翼 locator、目标脚/眼/中心；原点使用哪个实体的上下文。
4. **目标：** 创建者、瞄准者、乘客、当前目标、最近目标、命中者与奖励者分别定义；锁定还是重选，范围、视线、游戏模式、所有权/队伍规则分别记录。传送参与者不能直接复用伤害的 Combat.canHit。
5. **几何：** `distance` 的位置球形、`dx/dy/dz` 的原版选择箱、标签体素、物理碰撞、part 盒分别处理。尤其 `dx=0` 不能读成零体积点，必须用同版本命令选择器夹具验证；Slime `Size` 也不是直接的方块宽度。
6. **效果：** 数量、速度、持续、基础伤害类型、整数缩放/舍入、状态等级与受众、反射/反制能力；独立定义同 cast、多样点、多部件、多 tick 的去重窗口。
7. **结束：** 碰墙、碰人、到期、反制、主人离线、目标死亡、Boss 移除、卸载的每种结果；不能让所有终止原因都爆炸或都静默 discard。
8. **恢复与显示：** 必须保存/同步的状态、已执行事件、晚加入客户端的年龄/方向；服务端不能导入客户端渲染类。
9. **源与期望：** 使用固定输入/随机序列得出的事件序列与轨迹、当前原生反例、设计边界及未决事项。不能让“被测方法的返回值”同时生成预期值，形成自证测试。

例：D26 已确认“六个事件，每次一枚”，不等于“每隔 20 个游戏 tick”。先跟踪 leaf10 创建、leaf30 激活以及 block109/112 计分器推进，再写出每次发射的实际 tick。D14 的 inclusive 骰子边界、D35 的第一次生刺、D19 的到期末子步也须这样推导。测试只核对常量 6 或 20，不能证明实际 tick 发射次数正确。

## 4. 原生实现的统一底线

- 客户端仅显示；目标选取、伤害、随机结果、模式、传送、奖励在服务端处理。带方向/时间的状态同步给晚加入者，不重新从本地 tickCount=0 播放整段攻击。
- 普通伤害保留 Forge 取消/修改事件、无敌帧、护甲、抗性和吸收，不能直接 setHealth 绕过管线。保护/弱点只在确定阶段算一次；“原包按同基数加减”不意味着所有外部伤害修改器也改成同一乘区。
- 持续攻击有稳定 cast/encounter/owner 标识，去重按**源允许的伤害事件窗口**，不是整个招式终生只能命中一次，也不是每个采样点各打一份。part 映射保留实际命中部位与父实体归属。
- 目标搜索、递归/子步、地表搜索、反射跳数、连锁处理均有明确上限；边界不得穿过未知区块而假定空气。短期区块票到期释放，不能永久 forceload。
- 寿命默认按服务端游戏 tick 推进；除非有明确规格，不改成现实时间或让卸载/离线时间直接跳完剧情。客户端暂停/菜单与真正单机世界暂停区别处理。
- 保留 alpha.12 已完成的地表安全传送、缩放、使者 95 tick 远方入场、后撤悬空、300 格索敌、二转三落地和 Wingbeat；修其他项目不能退回地下生成或地面近战。
- 原包运行时命令不回流生产模组。开发测试可执行受控原命令作参照；生产代码不调用 function/命令解释器。
- 不默认重跑全量资源导入器。需要导出 locator 时只改必要导出步骤与产物，并核对生成 diff；源包仍只读。
- 测试新增类必须检查 JAR 排除规则。目前 [build.gradle](nyctocosm-native/build.gradle) 排除 `NativeGameTests*`/`ClientSmoke*`，不是自动排除任何名字带 Test 的类；新增其他开发专用类时同时更新打包约束和审计，防止泄漏进发布包。

## 6. 状态与“完成”的定义

清单为每个 D 项设置实施状态，本轮均为“待实施”。后续在该列写状态及对应验证记录链接：

| 状态 | 允许的依据 |
|---|---|
| 待实施 | 只有审计/设计 |
| 实施中 | 已有局部代码，仍有验收项未完成；注明子项 |
| 代码完成·待验证 | 计划中的代码已写完，但必要测试还没运行或尚未通过 |
| 自动验证通过·待实机 | 对应失败→通过回归、相关整体测试/构建已通过；必要客户端/多人/生存用例仍未验收 |
| 已验收 | 该项所有适用的自动与手工条件有记录；不适用项给理由。只有此状态可完整勾选该项 |
| 待决策 / 阻塞 | 明确缺哪个用户选择/环境能力，记录已做部分、证据及解除条件；不得冒充完成 |
| 已证伪 / 已批准保留差异 | 前者需双侧新证据，后者需用户明确接受；保留编号和历史，均不谎称“已经修复” |

一个 D 项含多个子机制时，只修一半仍是实施中；分组复选框只有所有成员验收后才勾选。有意保留差异不等于还原完成。V 项逐条写“未运行/部分运行/通过/失败及证据”，不因为 D 项编译成功全部勾选。

用户可以在“自动验证通过·待实机”时获得代码/JAR进行测试；此时交付应说“实现与自动验证完成，以下实机项待你测”，不能声称已完整复刻游戏体验。

## 7. 验证入口、隔离环境和产物

本轮只核对命令入口，**下面命令未在本轮执行**。[build.gradle](nyctocosm-native/build.gradle) 的 `gameTestRunDir` 是自定义可用属性。历史测试 116/116 只是阶段 32 记录，不是当前开工结果。

从 `nyctocosm-native` 目录开始，先检查 Java 17/Gradle 缓存；README 的 alpha.11 审计路径是旧示例，不照抄。PowerShell 示例：

```powershell
# 先把工作目录设到 nyctocosm-native；不使用相邻 MDK 的 wrapper。
.\gradlew.bat --version
# 如当前 JVM 不合适，使用本机实际存在的 Java 17；只在本进程设置，不修改系统配置。
# $env:JAVA_HOME='已检查存在的 Java 17 目录'

# 建立新的隔离运行目录，保留旧测试世界和所有用户存档。
$parityRun = 'run-parity-' + [Guid]::NewGuid().ToString('N').Substring(0,8)
New-Item -ItemType Directory -Path $parityRun -ErrorAction Stop
.\gradlew.bat runGameTestServer build --offline "-PgameTestRunDir=$parityRun"
if ($LASTEXITCODE -ne 0) { throw 'GameTest/build 失败；先保存日志和诊断，不能进入交付完成状态。' }

# 从本次 build.gradle 读取版本，只审计对应产物，不能任选 build/libs 中旧 JAR。
$parityBuildText = Get-Content -LiteralPath '.\build.gradle' -Raw
$parityVersionMatch = [regex]::Match($parityBuildText, "(?m)^version\s*=\s*'([^']+)'")
if (-not $parityVersionMatch.Success) { throw '未能解析版本；请核对实际构建配置。' }
$parityVersion = $parityVersionMatch.Groups[1].Value
$parityJar = Join-Path 'build/libs' ("nyctocosm-native-" + $parityVersion + ".jar")
if (-not (Test-Path -LiteralPath $parityJar)) { throw '本版本 JAR 不存在。' }
python .\tools\audit_native.py $parityJar
if ($LASTEXITCODE -ne 0) { throw '发布包审计失败。' }
Get-Item -LiteralPath $parityJar | Select-Object FullName,Length,LastWriteTime
Get-FileHash -LiteralPath $parityJar -Algorithm SHA256
git -c core.safecrlf=false diff --check
```

- 先建立当前基线；新增回归先确认旧原生失败，再修正，最后全套回归。现有入口是 [NativeGameTests.java](nyctocosm-native/src/main/java/com/flubberschnub/nyctocosm/NativeGameTests.java)。如选择按 batch 跑单项，先检查本机实际支持的参数，不能编造 Gradle flag；没有确认则跑全套。
- 原生已含一条把 Meteor 解释为“六波各二十枚”的测试。修改其预期时，保留旧失败证据与原包调用链，增加实际发射数/时序断言，不能只改常量测试并称已修。
- `--offline` 失败时先分清缓存/工具链问题与代码错误。首次下载、联网、安装工具按当前环境权限处理；不靠升级 Forge 或删除缓存绕过失败。
- 示例 Python 必须确实可用；审计脚本会覆盖 `docs/native-audit.json`。后续实施轮运行前保存当前报告的副本到本次验证目录，运行后保留新报告；记录修改来源。本提示词准备轮没有运行该脚本。
